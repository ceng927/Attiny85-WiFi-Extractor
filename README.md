## ATtiny85 硬軟體結合，搜尋網路使用紀錄
**針對實體接觸攻擊與 HID 的資訊安全研究**

專題使用的是 **ATtiny85** 模擬 USB 鍵盤（HID 裝置），作業系統面對 BadUsb 自動化輸入攻擊



##製作專題動機
在資安領域中，被大家討論的常常是防火牆以及各種軟體的問題，但是大家卻都忽略了硬體的實體攻擊方式
這個專題在討論如何利用ATtinty85偽裝成合法輸入裝置，在不處碰到防毒軟體的情況下，自動地提取系統內部資料。



##技術架構與核心技術

核心是 **軟硬體整合** 跟 **自動化腳本優化**，主要有兩個核心技術層面：

1. 軟硬體與 HID 編寫
 **硬體核心**： DigiSpark ATtiny85 開發板，具有微型化、低成本與內建 USB 的特點。
 **軟體編寫**： 由C/C++ 開發，導入 DigiKeyboard.h 函式庫，將attiny85列為 HID 虛擬鍵盤
 **電腦反應與時間差的問題**：
  在不同效能的電腦上進行實測後，發現老舊電腦對於鍵盤輸入的反應速度存在差異。為了確保過程中可以100%執行成功，我設計了延遲機制（delay）。在步驟 Win + R 喚醒系統、啟動終端機後加入合理的等待秒數，確保指令不會因為電腦卡頓而中斷或輸入錯位

2. 作業系統終端機與 .NET 優化 
在寫自動化指令時，比較了 Windows 系統的核心終端機架構：
 **CMD 與 PowerShell 的抉擇**：   
  傳統的命令提示字元 (CMD) 只能處理單純的文字，若要進行複雜的資料解析，要寫很長又容易出錯的批次檔，這時候就要用到 powershell 了
 **底層 .NET 架構的深度應用**：
  專題選擇直接呼叫 **PowerShell**。PowerShell 於 **.NET 物件架構**，讓腳本能夠直接操作物件，大幅提升資料處理效率。
   **編碼修正**：呼叫 .NET 的類別 [Console]::OutputEncoding = [System.Text.Encoding]::UTF8，成功解決台灣環境下常見的**中文 SSID 亂碼問題**。
   **資料篩選**：利用 .NET 的字串處理方法與 ForEach-Object 迴圈，將複雜的系統設定檔解析，解出 Wi-Fi 名稱與對應的明碼密碼。
